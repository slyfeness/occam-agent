# Qwen3.5-9B GRPO 常驻同步与 16×8 四卡试跑

2026-11-10 · BrowseComp-Plus · 4×A800 80GB · 每种批次规模各一次 FSDP FULL_SHARD 文本全参更新。两次作业均完成检查点写入、四个原 vLLM 副本的权重切换和检索恢复校验。

## 原生 token 前缀与拼接训练

CPU 诊断 `181203` 和 `181210` 核对了保存的原生 token、采样助手文本和下一轮实际提示。历史基线 `180554` 有 **3/173** 次前缀分歧，API 复测 `181174` 有 **1/164** 次。四个案例中，完整采样文本都仍是下一轮文本的前缀。对相同文本重新分词可复现下一轮保存的 token 前缀，因此分歧来自 token 重新切分。

四卡对照 `181211` 用 `181174` 的同一批 16 条已保存轨迹、同一权重和优势比较两条评分路径。候选仅在 token 历史严格延伸时拼接，工具观察保留为上下文，损失仍只作用于原生动作位置。

## 常驻更新与批量吞吐

推理沿用 [四卡复测配置](INFERENCE_CONFIG_181174.json) 的四个 BF16 TP1 实例、FlashAttention、CUDA Graphs、`align` 前缀缓存、每实例并发上限 32、65,536 token 上下文和 T=1 / top_p=1 / top-k 关闭。常驻路径在训练前让 vLLM 休眠、把检索编码器移到 CPU，更新后由原进程读入新 BF16 快照并清除旧缓存。检索编码器随后回到 GPU。同步通过共享文件中的推理快照，表中分别计量导出与原地载入。首次常驻尝试 `181217` 在生成前因 vLLM 休眠内存池与 `expandable_segments` 冲突退出。后续仅为 vLLM 进程移除该设置，HF 训练保持原分配器配置。
