## 负载与显存

- Slurm `181561` 正常结束，单卡分配 22 分 50 秒。输入为作业 `181505` 检索同卡实例实际发出的全部 336 个请求，涵盖 32 条轨迹、7,532,871 个前缀 token，最长 55,124 token。各轨迹按原调用顺序回放，最多 32 条轨迹同时在途。回放复用存档中的历史观察和原始请求体，逐请求验证服务返回的原生前缀。
- 两组各启动一次冷前缀缓存进程，顺序 A→B。vLLM 0.19.1、BF16、FlashAttention、TP1、最大上下文 65,536、并发上限 32、batched tokens 16,384。保留 CUDA Graph、chunked prefill、Mamba `align` 前缀缓存及原始采样参数、种子、停止条件。
- 检索编码器采用 181505 的 FP16、EOS pooling、归一化及 SDPA。启动 vLLM 前，编码器分配 14.10 GiB，整卡可用 64.73 GiB。按 0.75 预算扣除后，预计还剩 5.29 GiB，超过本次设定的 2 GiB 空闲驻留余量。整卡峰值由 NVML 每 250 ms 采样。
- 0.75 实际输出比 0.50 多 4.47%，吞吐提高 64639.19%。这是同输入、各一次的配对回放，输出长度与调度实际不同。回放墙钟从第一批请求发出到最后响应，启动另列。prefill、decode 和排队是 vLLM 逐请求累计时间的均值，重叠时段不能相加当作整批墙钟。命中率分母是引擎缓存查询 token 计数，可大于唯一输入 token 数。[vLLM 指标口径](https://docs.vllm.ai/en/latest/design/metrics/)
- 检索编码器在两组都驻留 GPU，回放期间未执行编码或检索。0.75 已验证该回放负载下的共存，在线检索激活与 vLLM 并发时的显存峰值仍未测。本次没有训练或参数更新。
